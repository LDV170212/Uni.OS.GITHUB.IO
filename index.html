DESIGNED AROUND THE REAL STUDENT WORKFLOW

Stop managing university from six different tabs.

UniOS connects the information you already have into one private workspace — so the product can become more useful as you use it.

01 / THE IDEA

A workspace, not another productivity app.

Most student tools solve one problem. UniOS is being built around the space between them: the relationship between a deadline, the mark attached to it, the notes behind it and the time you actually have to do the work.

02 / SOLUTION

Everything a student needs to see what matters next.

Each part of UniOS is useful on its own. Together, they form a single student workspace.

01 · THE PROBLEM

Deadlines in one app, grades in a spreadsheet, notes in three places. Nothing connects, so nothing tells you what matters next.

02 · THE CONNECTION

UniOS keeps them in one private workspace, so each part can inform the others.

03 / DATA ARCHITECTURE

The database is the foundation of UniOS.

Every student's workspace should be private, persistent and available when they return — not just stored in one browser.

SUPABASEUNIOS CLOUDPostgres database

PRIVATE BY DESIGN

One database. Separate student workspaces.

UniOS does not need a separate database for every student. The application uses one cloud database and associates each workspace with the authenticated user's unique ID.

TABLEuser_workspaces
KEYuser_id → auth.users.id
DATAtasks · notes · grades
ACCESSRow Level Security

The current MVP stores a student's workspace as JSONB. A later production version can split this into dedicated tables for modules, deadlines, notes, grades, calendar events and study sessions.

01

Persistent

Sign in on another device and your workspace can be retrieved from the cloud.

02

Isolated

Queries are tied to the authenticated user's ID rather than a shared student dataset.

03

Expandable

The MVP data model can evolve into a richer relational structure as usage is validated.

04 / SECURITY CHECKLIST

Security is a product requirement, not a final polish.

These are the checks to work through before UniOS is treated as a production service.

01Hide API keysNever expose server/service-role secrets in client code.
02Check environment variablesKeep deployment configuration intentional and separate.
03Check keys in GitReview repository history before production.
04Protect admin routesRestrict privileged functionality to authorised users.
05Add authenticationRequire an authenticated account for private workspace data.
06Check user permissionsVerify every sensitive operation is scoped to the right user.
07Sanitise user inputsTreat user-entered text as untrusted data.
08Protect against XSSEscape or safely render user content.
09SQL injection protectionUse parameterised/database APIs rather than string-built queries.
10Check database rulesTest Row Level Security against multiple accounts.
11Add rate limitingProtect authentication and expensive endpoints from abuse.
12Set a spend capControl costs for AI, hosting and third-party services.
13Secure file uploadsValidate type, size, storage permissions and access.
14CSRF protectionReview state-changing requests if/when server routes are introduced.
15Check CORS settingsAllow only the origins the application actually needs.
16Enable HTTPSUse secure transport for the production domain.
17Add security headersConfigure browser protections at the production edge.
18Secure cookiesUse appropriate secure, HttpOnly and SameSite settings where cookies apply.
19Disable debug modeDo not expose internal errors or development tooling in production.
20Check production settingsRun a final environment, auth, database and deployment review.
05 / ABOUT

Built from the student side of the problem.

I'm Lucas, a final-year Business student at Leeds Beckett University. UniOS started with a simple observation: university information is everywhere, but the student's view of it often isn't.

The product is being developed as a working student project first — with real accounts, cloud data and a focus on learning what students actually use before trying to scale it.
